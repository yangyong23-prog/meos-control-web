# meri-ui-interaction-guidelines

用途:
- 通用交互规范的统一入口与准则说明。

适用场景:
- 需要核对加载/空状态/提交反馈等交互细节。
- 需要统一页面适配、滚动与导航状态保持规则。
- 需要核对表单校验、未保存保护、增删等交互标准。
- 需要快速查阅组件交互细节与动画参数。

一、 页面加载与状态反馈 (Page Loading & Feedback)

1. 加载机制 (Loading)
- 优先原则: 默认进入页面加载数据时，严禁使用“暂无数据”的空状态代替加载过程，必须显示加载动画。
- 加载类型区分:
  - 按钮加载: 适用于轻量级提交（如“保存”）。点击后按钮变灰并显示 Loading，不可再次点击，但允许用户浏览页面其他内容（如导航）。
  - 全局/局部加载（阻断式）: 适用于数据量大、需长时间校验或长表单提交。使用整页或局部遮罩，防止用户在提交过程中修改其他内容或重复点击。
  - 下拉/异步加载: 下拉选项若需从服务器拉取，面板内显示 Loading；即时搜索时，结果面板内显示局部 Loading。

2. 提交反馈 (Submission Feedback)
- 成功状态: 通常 Message 提示“保存成功”，并在延迟 1 秒后自动跳转回上一页。
- 失败状态:
  - 按钮加载模式: Message 提示“提交失败，请重试”，停留在当前页以便修改。
  - 全局加载模式: 移除遮罩，Message 提示错误。

3. 空状态与异常 (Empty & Error States)
- 布局位置: 始终居于内容区域的水平及垂直居中。
- 场景细分:
  - 页面级: 整个页面无数据，由“占位图 + 说明文本（如‘暂无内容’） + 操作按钮（可选，如‘去创建’）”构成。
  - 局部/卡片级: 某个具体模块无数据，仅需“说明文本”。
  - 表单占位: 表单场景下若无数据，也需要有占位的空状态。
  - 异常状态: 接口报错或断网时，显示“未获取到数据”。

二、 屏幕适配与布局规则 (Layout & Adaptation)

1. 顶部筛选区适配 (1280px/宽/窄屏)
- 固定与流动原则:
  - 固定项: 返回按钮、Tab 标签、单个搜索/筛选框宽度及间距固定。
  - 流动项: 屏幕变窄（如 1280px）时，筛选条件应自动换行，不应压缩筛选框的宽度。
- “三位一体”强制跟随逻辑:
  - “展开/收起”、“查询”、“重置”这三个按钮必须作为一个整体，始终跟随在最后一个筛选条件之后。
  - 若因空间不足导致最后一个筛选条件换行，这三个按钮必须集体移动到下一行，绝不能拆散（例如留一个在上行）。
- 默认折叠策略:
  - 一般进入: 窄屏下若筛选条件超过一行，默认收起，只展示一行。
  - 外部带参进入: 仅当从外部（如消息通知）带参数跳转进入时，默认全部展开，以便用户确认过滤条件。

2. 滚动与边界交互 (Scrolling & Boundaries)
- 滚动条位置: 只要页面存在滚动，滚动条应始终保持在盒子边缘内侧 2px 处。
- 下拉组件防跟随: 在看板、详情、弹窗等场景中，当页面发生滚动时，所有下拉面板、Popover、选择器浮层应自动消失/收起，严禁跟随页面滚动（防止与导航栏分离或遮挡）。
- 防遮挡: 下拉面板在触底或触边时，需自动调整弹出方向（如向上弹出）。

三、 导航与状态保持 (Navigation & State Retention)

1. 状态记录核心原则 (Keep-Alive)
- 核心规则: 除非特殊说明，系统应默认遵循“原样保留”原则。
- 场景区分:
  - 内部返回/Tab 切换/下钻返回: 必须全量保留原页面状态。包括: 滚动条位置（自动锚定）、筛选条件（含输入内容）、展开/收起状态、分页页码、排序方式。
  - 外部/首次进入:
    - 首次进入: 状态初始化（无筛选，滚动置顶，默认收起）。
    - 外部带参跳转: 重置但应用带入的参数，滚动置顶，默认展开筛选区。

2. 跳转与路由
- 新窗口打开: 若需浏览器新开窗口，必须给予 Tips 提示或图标示意。

四、 表单与数据录入 (Forms & Data Entry)

1. 布局与校验
- 布局规范: Label 左对齐；必填标记（*）跟随文本（间距 4px）；组件上下间距不少于 16px 以容纳报错信息。
- 自动定位报错: 点击提交若校验未通过（特别是长表单），页面必须自动滚动定位至第一个报错的字段位置。
- 重复性校验: 系统需检测“名称”或“时间段”是否重复，并在保存或失焦时提示错误。

2. 数据保护 (Unsaved Changes Protection)
- 触发场景: 用户已输入但在未保存状态下点击“返回”、浏览器后退、切换 Tab 分组、或点击弹窗右上角“X”。
- 二次确认弹窗逻辑:
  - 取消: 关闭弹窗，停留在当前页，不做改变。
  - 直接离开: 不校验，不保存，直接跳转/关闭。
  - 保存并离开: 若校验通过 -> 提示成功并跳转；若校验失败 -> 关闭弹窗，回到原页面并定位错误项（不跳转）。

3. 动态增删 (Add/Delete)
- 添加按钮: 可在列表下方，也可设计为底部吸底（Maximum height 后）以便随时可见。
- 新增行为: 新增组应出现在列表最下方，并自动滚动至可见区域，建议配合高亮动画。
- 上限控制: 达到数量上限时，添加按钮置灰 (Disabled) 并显示 Tooltip 提示上限原因。
- 删除逻辑:
  - 需提供醒目删除图标（Hover 显示 Tooltip）。
  - 删除操作建议触发二次确认。
  - 删除中间组时，下方组向上补位；剩最后一组时隐藏删除图标。

五、 通用组件交互细节 (Component Interactions)

1. 文本与字体
- 截断提示: 侧边栏、表格等任何出现文本截断（...）的地方，Hover 必须显示完整内容的 Tooltip。
- 字体规范:
  - 中文环境: Microsoft YaHei。
  - 数据/大屏/统计看板数字: 使用 Persagy V2.0 字体。

2. 鼠标手势
- 规则: 可点击元素=手指；不可点击=指针；禁用元素=禁用手势；可拖拽=拖拽手势。

3. 下拉与选择器
- 搜索功能: 单选/多选下拉框选项超过 7 个时，必须增加搜索框。
- 多选操作: 若无外部“查询/重置”按钮，多选下拉底部必须带有“全选”功能以及“取消/确定”按钮作为统一触发动作。
- 树形结构: 默认全部收起。例外: 若收起时只有一级（无子级或子级很少），则默认展开第一级。

4. 搜索框 (Search)
- 触发机制: 明确是“回车/点击按钮触发”还是“输入即时触发”。
- 清除逻辑: Hover 时才显示清除（X）按钮；点击清除后自动触发重置查询，且焦点必须保留在搜索框内。
- 层级引导: 若在“非全部”层级下搜索无果，需提示“该列表暂无内容，请切换至「全部」查找”，并提供一键跳转。

5. 表格 (Table)
- 斑马线: 当表格占比页面 70%~80% 以上时，需开启斑马线样式（Grey 50，从第二行起）。分组表格、树表格不遵循此规范。如果是换行的表格就不展示斑马线。
- 列宽拖拽: 支持拖拽，但操作列（详情/删除）需始终固定在右侧。

6. 禁用状态 (Disabled)
- 所有禁用的输入框或按钮，鼠标 Hover 时必须显示 Tooltip 解释具体的禁用原因（如“权限不足”）。

六、 动画参数标准 (Animation Specs)

- 高亮动画: 针对新创建或搜索命中的数据，使用闪烁两次的高亮提醒。
- 时序参数: 300ms(淡入) -> 200ms(维持) -> 300ms(淡出) -> 200ms(维持) -> 300ms(淡入)。

## Context

当前系统已支持温度、CO₂、湿度的环境品质标准配置与 Dashboard/模型视角/品质视图/临时需求中的消费。本期新增压差标准：在环境品质目标中新增压差全局开关与上下限配置，黑名单增强压差过滤，并在 Dashboard/模型/品质/临时需求/需求目标中消费压差标准。同时，压差标准是否展示与空调模板的"压差"启用状态联动。

## Goals / Non-Goals

**Goals:**
- 空调运行标准新增压差标准配置（全局开关、上下限、数值校验）
- 黑名单"按 IOT 监测"新增"未交付压差数据的空间"选项
- Dashboard 新增压差分布统计环图与空间列表压差筛选染色
- 模型视角新增压差分布统计（全楼/楼层），压差无调度时隐藏调度数量
- 品质视图全楼/楼层模型按压差染色
- 临时需求新增压差目标设定
- 需求目标新增压差标准显示
- 配套国际化

**Non-Goals:**
- 不涉及新设备类接入（独立 change）
- 不涉及半剖图改造（独立 change）
- 不涉及压差调度配置（PRD 明确压差不配置调度）

## Decisions

### 1. 压差标准配置复用现有空调模板配置体系

决策：压差全局开关与上下限沿袭现有温度/湿度的配置模式——全局配置控制是否开启，开启后可录入上下限。

原因：与现有环境品质目标配置体验一致，用户学习成本低。关闭时清空标准值。

### 2. 压差区间计算按空间实例获取标准

决策：每个空间按自身实例化规则获取压差上下限标准，无法获取时判定为"无标准"。

原因：PRD 明确"每个空间都有自己的压差区间标准"。

### 3. 压差分布统计与现有温度/CO₂分布采用相同组件

决策：Dashboard 环图、模型统计复用时已存在的品质分布统计组件，新增压差分支逻辑。

原因：减少重复开发，展示形态与温度/CO₂一致。

## Risks / Trade-offs

- [空调模板未启用压差时全部隐藏] → 前端各消费模块统一判断模板压差开关状态后渲染
- [压差目标临时需求接口需补充] → 后端需补充 /interventionTaskConfig/list 接口的压差目标查询
- [黑名单提示语修改影响现有文案] → 需确认现有 i18n key 是否需新增或覆盖

## Migration Plan

1. 空调运行标准配置新增压差标准（全局开关 + 上下限）
2. 黑名单配置新增"未交付压差数据的空间"
3. Dashboard 压差分布环图 + 空间列表压差筛选染色
4. 模型视角压差分布统计
5. 品质视图压差空间染色
6. 临时需求压差目标设定 + 需求目标显示压差标准
7. 联调与 i18n

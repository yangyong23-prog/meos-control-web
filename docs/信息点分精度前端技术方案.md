## 一、背景与目标

信息点分精度查询目前分为两大类：

1. **带特定请求头查询**：云端模块通过 `GET /strategyIntervention/getInfoCodeDataTimeAndPrecisionType`（边端走 DTP 前缀、云端走 MEOS，目前均走云端）预先获取 `startTime / endTime / ipTypes`，写入全局 `headerConfig`，之后该模块下所有 IOT 数据请求由 axios 拦截器统一注入请求头 `IPType / IPDataStartTime / IPDataEndTime`。
2. **不带/不消费请求头查询**：或前端 payload 自带分精度（如运行监控看板，payload 优先），或后端自行处理精度（老冷源效率参数、SSE 推数等），前端无感知。

本期改造目标（前端侧）：

- 壳配置（持久化数据查询逻辑 =「查询距离当前最新的数据」）时：系统图页面与空间三维模型**不再显示"更新时间"**。
- 在指定模块、指定接口上**追加标记请求头 `removeDefaultIpType = true`**（原有请求头传参保持不变），由后端据此区分是否真正消费分精度。
- 改造范围评估与产品测试同步：冷源、冷热源、空调冷源、空调热源、空调冷热源；**热源模块暂不改造**（历史无分精度请求头，老系统保持不动）。

## 二、现状链路梳理（代码事实）

### 2.1 分精度请求头注入点（全局唯一）

`src/utils/http.ts`（axios request 拦截器，约 L200-209）：

```ts
if (!isEdge()) {
    const { base } = useStore();
    const { runningMonitorType = '', IPType = '', startTime = '', endTime = '' } = base.headerConfig;
    Object.assign(config.headers, {
        runningMonitorType,
        IPType,
        IPDataStartTime: startTime,
        IPDataEndTime: endTime
    });
}
```

要点：

- **边端（isEdge()）不注入**任何分精度头，与梳理文档"边缘端不带参"一致。
- 头来源为 pinia 全局 store `baseStore.headerConfig`（`src/store/baseStore.ts`），字段 `runningMonitorType / IPType / IPDataStartTime / IPDataEndTime`（注意 store 字段名与 header 名的映射：`startTime → IPDataStartTime`，`endTime → IPDataEndTime`）。
- 该拦截器是**全局**的：凡是 `base.headerConfig` 非空的页面，其下所有请求都会带头——这正是"影响面广"的根因，也是本方案用 `removeDefaultIpType` 标记做收口的出发点。

### 2.2 headerConfig 的生产与消费

- **生产**（`src/views/Common/SystemsAndControl/hooks/useBaseDataHook.ts` `getUpdateTime()`）：调 `getInfoCodeDataTimeAndPrecisionType` 后 `base.setHeaderConfig({ IPType: ipTypes[0], startTime, endTime, runningMonitorType })`。注意 `IPType` 固定取 `ipTypes[0]`。
- **生命周期**（`baseStore.setHeaderConfig`）：路由切换时 `src/router/index.ts` 调 `setHeaderConfig()`（无参 = 清空 + 清定时器）；模块内带参调用则合并写入，并启动 60s 轮询 `fetchUpdateTime()` 刷新时间。
- **消费（UI 层"更新时间"显示）**，显示条件均为 `runningMonitorType 存在 && !isEdge()`：
  - `src/components/systemGraphHeader/index.vue`（系统图 header）
  - `src/views/ACAC/left/Header.vue`
  - `src/views/ACoperationMonitoring/operationMonitoringMain/components/header.vue`
  - `src/views/operationMonitoring/operationMonitoringMain/components/header.vue`
  - `src/views/test/RelationChartMemoryTest/...`（测试页，不在改造范围）
- **其它消费**：`src/views/SEEA/right/OperatingControl.vue` 直接读取 `base.headerConfig.startTime` 决定是否调用 `batchQueryPeriodData`。

## 三、总体设计

### 3.1 设计原则

1. **收口单一注入点**：所有改动基于现有 `http.ts` 拦截器 + `baseStore.headerConfig`，不新增平行链路。
2. **白名单式标记**：以"接口级白名单 + 请求头标记"方式精确控制 `removeDefaultIpType`，默认不标记，避免全量回归风险。
3. **壳配置驱动 UI**：更新时间的显隐由壳配置统一控制，收敛到一处 store getter，各 header 组件只消费。
4. **边端零影响**：所有新增逻辑均在 `!isEdge()` 分支内。

### 3.2 壳配置：更新时间显隐（评审后确定）

**数据来源**：前端另调 `shellConfig/query`（`src/apis/xshellConfiguration.js` `shellConfigQuery`）。当【持久化数据查询逻辑 = 查询距离当前最新的数据】时，消费时间间隔配置（默认 1h，范围 1–168）。

**方案**：

1. `baseStore` 新增状态与 getter：

```ts
queryLatestDataMode: boolean;      // 默认 false（查询失败/未返回时维持旧行为：显示更新时间）
latestDataIntervalHours: number;   // 默认 1，范围 1-168
// getter
getShowUpdateTime: state => (base) => Boolean(base.headerConfig.runningMonitorType) && !isEdge() && !state.queryLatestDataMode;
```

2. **查询时机与缓存（评审结论 #4）**：封装 `useShellPrecisionConfig()`（`src/hooks/`），在各模块入口（`useBaseDataHook`、`ACoperationMonitoring/use-utils.ts` 等 `setHeaderConfig` 调用点旁）调用；内部按 **projectId 会话级缓存**，重复并发去重；项目切换时失效。
3. **60s 轮询保留（评审结论 #1）**：`fetchUpdateTime()` 轮询不动，仅 UI 显隐受 `queryLatestDataMode` 控制；注意 `fetchUpdateTime` 每次写入的 `id` 时间戳被 `useControlBoardHook` watch，属功能性行为，不改。
4. **显隐收敛**：4 处 header 组件（`systemGraphHeader`、`ACAC/left/Header`、两处 `operationMonitoringMain/components/header`）改读 `getShowUpdateTime`。三维模型视图复用同一 header（如 ACAC MapView 模式），自动覆盖；其余 `update_time_colon` 引用为数据点自身时间，与本次无关。`systemGraphHeader` 的 `showUpdateTime` props 优先级保留。

### 3.3 `removeDefaultIpType` 标记注入（按模块/路由区分的 path 注册表）

**背景**：不同模块可能调用同一接口，但仅部分模块需要打标（如接口 X 在「冷源」需要、其它模块不需要），因此注册表必须带模块/路由维度。

**实现**：`src/apis/precisionWhitelist.ts` 维护**模块级规则表** `PRECISION_MODULE_RULES`，每条规则 = 模块标识 + 路由模式（支持 `:majorCode` 动态段）+ 可选 majorCode 白名单 + 接口列表（精确 `exact` / 前缀 `prefixes` 两档）。`http.ts` 拦截器与 `SSEClient` 调用 `matchPrecisionApi(url)`，其内部取 `router.currentRoute` 当前路由上下文先匹配模块规则、再匹配接口列表；返回命中的模块标识用于 `console.debug` 排查日志（不随请求发送）。

```ts
export interface PrecisionModuleRule {
    module: string;            // 模块标识（排查用）
    routePatterns: string[];   // 如 '/operation-monitor/:majorCode/graph'
    majorCodes?: string[];     // 可选：ACCC=冷源 / ACCI=冷热源；热源 ACAH 不配置
    exact: string[];
    prefixes?: string[];
}
```

> **回滚 = 删除/注释对应规则或条目**，可逐模块、逐接口回滚；不做前端灰度开关，灰度由后端控制。
> 原"逐 API 函数加 header"方案作废；"全局 path 白名单（不分模块）"方案亦作废（无法满足同接口分模块差异打标）。

### 3.4 需打标的接口与模块范围（以最终清单为准）

依据梳理文档第三节 + 《PRD-260901-接口改造最终清单.md》：

### 3.5 特殊场景处理

1. **SSE 订阅（评审结论 #9：清单包含 SSE，已确认走 fetch-event-source 封装）**：实际链路为各 hook（`useSinglePOSTSSEClient`、`useEquipDetailSSE` 等）→ `SSEClient`（`src/utils/SSEClient.js`）→ `FetchEventSourceAdapter`（`src/utils/FetchEventSourceAdapter.ts`，基于 `@/utils/fetch-event-source`）。**改造点收敛在 `SSEClient._initOptions`**（唯一 headers 组装处）：按 `precisionWhitelist` 匹配 `options.url`（`server-event/sse/subscribe`），命中则在 headers 中追加 `removeDefaultIpType: 'true'`。一处改动覆盖全部 SSE 订阅点，无需改各业务 hook。
2. **payload 自带分精度的页面**（如运行监控看板 `batchQueryPeriodData`）：payload 优先于请求头，后端已按 payload 处理，前端**不需要**打标，保持现状。
3. **qiankun 微前端**：本方案不改 `headerConfig` 结构，仅新增状态字段，向后兼容；需确认子应用是否共享宿主 `baseStore`。
4. **路由切换/刷新**：`router/index.ts` 已在切换时清空 headerConfig；壳配置缓存按 projectId 失效重建。
5. **多 ipTypes 场景**：现状固定取 `ipTypes[0]`，不改；后续若支持多精度并存另行评估。

## 五、测试要点

- **显隐**：
  - 壳配置 =「查询同一时刻点数据」→ 更新时间正常显示，数值随 60s 轮询刷新；
  - 壳配置 =「查询距离当前最新的数据」→ 系统图页面 + 空间三维模型均不显示更新时间；
  - 边端（edge 构建）任何配置下均不显示、请求不带头。
- **请求头**：
  - 白名单内接口请求头含 `removeDefaultIpType: true`，且原 `IPType/IPDataStartTime/IPDataEndTime` 仍按现状携带；
  - 白名单外接口**不含**该标记头（拦截器 delete 兜底）；
  - payload 自带分精度的看板接口行为不变。
- **范围回归**：冷源、冷热源、空调冷/热/冷热源的关系图/模型图、设备详情、设备列表、控制台；热源模块确认无任何改动；生活给水/气源/光伏控制台差异点回归。
- **异常链路**：分精度接口失败（超时/500）时页面降级（headerConfig 为空 → 不带头，页面仍可用）。

## 六、风险与回滚

- **风险 1**：打标遗漏 → 后端仍按默认分精度返回，表现为数据时间戳不一致。缓解：打标 checklist 逐条验收 + 抓包比对。
- **风险 2**：标记头误扩散 → 拦截器统一 delete 兜底，仅显式声明才透传。
- **风险 3**：壳配置查询失败 → `queryLatestDataMode` 默认 false（显示更新时间，维持旧行为），不阻断页面。
- **回滚**：删除/还原 `precisionWhitelist.ts` 引用即可逐接口回滚；显隐改造由壳配置兜底可控。
